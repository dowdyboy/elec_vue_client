# 14 - 网络通信

> 对应源码：`src/main/features/network.ts` | 演示页：网络通信

## 一、原理

桌面应用网络请求的两种主流方案：

| 方案 | 位置 | 优点 |
|------|------|------|
| HTTP（axios） | **主进程** | 绕过浏览器 CORS、统一鉴权/错误处理/重试 |
| WebSocket（socket.io-client） | **渲染进程** | 浏览器原生能力，双向实时推送 |

**为什么 HTTP 放主进程？**
- 渲染进程的 `fetch` 受 CORS 限制，而主进程的 Node.js HTTP 客户端没有
- 便于集中管理 token、日志、超时重试

**为什么 WebSocket 放渲染进程？**
- 浏览器原生支持 WebSocket，无需主进程中转
- 实时数据流直接驱动 UI，链路更短

## 二、关键代码

```ts
// ── 主进程：HTTP 封装 ──
import axios from 'axios'

ipcMain.handle('network:httpGet', async (_e, url) => {
  try {
    const response = await axios.get(url, {
      timeout: 10000,
      validateStatus: () => true // 让 4xx/5xx 也返回数据
    })
    return { ok: true, status: response.status, data: response.data }
  } catch (error) {
    return { ok: false, error: error.message }
  }
})

// ── 渲染进程：WebSocket（socket.io-client）──
import { io } from 'socket.io-client'

const socket = io('https://your-server.com')
socket.on('connect', () => socket.emit('message', 'hello'))
socket.on('message', (data) => console.log('收到:', data))
```

## 三、复制到新工程的步骤

**HTTP**：
1. 复制 `src/main/features/network.ts`
2. `index.ts` 中调用 `registerNetwork()`
3. 渲染进程：`const res = await window.api.network.httpGet(url)`

**WebSocket**：直接复制渲染进程的 `io()` 用法（需 `npm i socket.io-client`，本工程已安装）。

## 四、最佳实践

- **超时必设**：`timeout: 10000`，避免请求挂死
- **统一错误结构**：返回 `{ ok, data | error }`（与文件系统模块一致），页面统一处理
- **鉴权**：token 在主进程统一注入 header，渲染进程无感知
- **socket 清理**：页面卸载时 `socket.disconnect()`，避免连接泄漏

## 五、扩展：DNS 解析与在线状态

**DNS 解析**（`network.ts` 的 `network:resolveDns`）：

```ts
const result = await net.resolveHost('github.com')
// Electron 30+ 返回结构（⚠️ 旧版为 addresses，新版为 endpoints，见下方踩坑）：
// result.endpoints: [{ address: '140.82.121.4', family: 'ipv4' }, ...]
```

**⚠️ 踩坑（本工程实测）**：Electron 30+ 将 `net.resolveHost` 的返回结构从
`{ addresses: [{ address, family: number }] }` 改为
`{ endpoints: [{ address: string; family: 'ipv4' | 'ipv6' | 'unspec' }] }`。
按旧结构转型访问 `result.addresses` 会得到 undefined，`.map` 直接抛
"Cannot read properties of undefined (reading 'map')"。升级 Electron 后务必同步此结构。

**在线状态**（`netStatus.ts` + 浏览器事件）：主进程 `net.isOnline()` 查询；
`online/offline` 是渲染进程浏览器事件（preload 已封装为 `window.api.net.onStatus`）。
注意它只反映系统网络连通性，业务探测用 HTTP 请求。

> 补充：主进程 axios 走 **Node 网络栈**，不使用系统代理（需要时自行配置
> `session.setProxy`，见 docs/28）；渲染进程 fetch 则走 Chromium 栈受系统代理影响。
> 教学演示地址建议按"本地回环 > 稳定站点 > 外网 JSON"选择（本页默认走
> httpServer.ts 的本地接口，100% 可达）。

## 六、扩展：HTTP 服务器（`src/main/features/httpServer.ts`）

主进程即服务器（node:http）：

```ts
const server = http.createServer((req, res) => {
  res.setHeader('Content-Type', 'application/json')
  if (req.url === '/api/info') res.end(JSON.stringify({ app: 'demo' }))
})
server.listen(8765, '127.0.0.1')
```

渲染进程：`window.api.httpServer.start(8765)` → 直接 `fetch('http://127.0.0.1:8765/api/info')`
（无跨域限制，服务器已加 CORS 头）。场景：应用内 API mock、局域网共享。
与 axios（客户端）互补——本模块是"服务端"视角。

**⚠️ 踩坑（本工程实测）：渲染进程 fetch 受页面 CSP `connect-src` 约束**

点「访问本机接口」报 `TypeError: Failed to fetch` 的典型根因是 CSP——
fetch 到 `http://127.0.0.1:8765` 相对页面源是**跨源连接**，被 index.html 的
`connect-src` 在请求发出前拦截（Console 会打印 "Refused to connect ... violates
Content Security Policy"）。注意：**CORS 头 ≠ CSP 放行**——CSP 拦截发生在 CORS 之前，
服务器加 `Access-Control-Allow-Origin` 也无济于事。

本工程已在 index.html 放行回环地址（仅 127.0.0.1/localhost，最小权限）：

```html
<meta http-equiv="Content-Security-Policy"
      content="... connect-src 'self' elec-fs: http://127.0.0.1:* http://localhost:*" />
```

> 同理：渲染进程直接用 socket.io 连接外部服务器时，也需在 connect-src 放行目标域名；
> 而走主进程 axios 的请求（Node 网络栈）不受页面 CSP 约束——这也是主进程代理
> 请求方案的另一优势。

## 七、WebSocket 自闭环演示（socket.io，`src/main/features/socketServer.ts`）

与 HTTP 服务器（第六节）互补的"实时通信"教学：**主进程起 socket.io 服务 →
渲染进程 socket.io-client 直连回环地址**，零外网依赖即可验证 WebSocket 两大核心价值：

| 能力 | HTTP（请求-响应） | WebSocket（本模块） |
|------|------------------|--------------------|
| 双向实时 | 每次交互都要新请求 | echo 即时回显，长连接复用 |
| 服务端推送 | 服务器无法主动发起 | 每秒 tick 推送（时间/在线数） |

```ts
// 主进程（socketServer.ts）：node:http 上挂 socket.io（WebSocket 握手经 HTTP Upgrade）
import { Server as SocketIOServer } from 'socket.io'
const server = http.createServer(/* ... */)
const io = new SocketIOServer(server, { cors: { origin: '*' } })

io.on('connection', (socket) => {
  socket.emit('welcome', { message: '已连接' })          // ① 连接即推送
  socket.on('message', (data) => socket.emit('echo', data)) // ② 双向回显
  const timer = setInterval(() => socket.emit('tick', {...}), 1000) // ③ 服务端推送
  socket.on('disconnect', () => clearInterval(timer))
})
server.listen(8766, '127.0.0.1')

// 渲染进程（socket.io-client 直连回环；CSP connect-src 已放行 127.0.0.1:*）
const socket = io('http://127.0.0.1:8766')
socket.on('welcome', (d) => console.log(d.message))
socket.on('echo', (d) => console.log('回显:', d.received))
socket.on('tick', (d) => console.log(d.time, d.clients))
socket.emit('message', '你好，主进程！')
```

**复制步骤**：`npm i socket.io` → 复制 `socketServer.ts` → `registerSocketServer()`
→ 渲染进程 `window.api.socketServer.start(8766)` + 上方客户端代码。

**注意**：生产环境连接外网服务器时，CSP `connect-src` 需放行目标域名；
socket.io 默认先 HTTP 长轮询再升级 WebSocket，均受 connect-src 约束。
