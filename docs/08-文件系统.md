# 08 - 文件系统

> 对应源码：`src/main/features/fileSystem.ts` | 演示页：文件系统

## 一、原理

渲染进程默认**没有**文件系统访问能力（安全隔离）。所有文件操作必须经主进程 `fs` 执行。

本工程提供最小封装：所有 IPC 返回 `{ ok, data? | error? }`，异常不抛到渲染进程，方便页面直接展示错误。

**生产工程必做**：路径白名单校验（限制只能读写指定目录），防止渲染进程被注入恶意代码后任意读写文件。

## 二、关键代码

```ts
import { promises as fs } from 'fs'

// 统一异常包装
async function safe<T>(fn: () => Promise<T>) {
  try {
    return { ok: true, data: await fn() }
  } catch (err) {
    return { ok: false, error: err.message }
  }
}

ipcMain.handle('fs:readFile', (_e, filePath) =>
  safe(async () => (await fs.readFile(filePath, 'utf-8')).toString())
)

ipcMain.handle('fs:writeFile', (_e, filePath, content) =>
  safe(async () => {
    await fs.mkdir(dirname(filePath), { recursive: true }) // 自动建父目录
    await fs.writeFile(filePath, content, 'utf-8')
    return '写入成功'
  })
)

ipcMain.handle('fs:listDir', (_e, dirPath) =>
  safe(async () => (await fs.readdir(dirPath, { withFileTypes: true })))
)
```

## 三、复制到新工程的步骤

1. 复制 `src/main/features/fileSystem.ts`
2. `index.ts` 中调用 `registerFileSystem()`
3. 渲染进程：

```ts
const result = await window.api.fs.readFile('C:/path/file.txt')
if (result.ok) {
  console.log(result.data)
} else {
  console.error(result.error)
}
```

## 四、进阶：拖拽获取真实路径

浏览器拖拽只能拿到 `File` 对象（无系统路径）。Electron 中通过 `webUtils.getPathForFile` 获取真实路径（在 **preload** 中暴露，渲染进程即可使用）：

```ts
// preload/index.ts
import { webUtils } from 'electron'

fs: {
  // ...
  getPathForFile: (file: File) => webUtils.getPathForFile(file)
}

// 渲染进程拖拽处理
function onDrop(event: DragEvent): void {
  const files = Array.from(event.dataTransfer?.files ?? [])
  const paths = files.map((file) => window.api.fs.getPathForFile(file))
}
```

拿到真实路径后，即可继续走 `fs:readFile` 等 IPC 完成读写。

## 五、进阶：拖拽文件出窗口（webContents.startDrag）

反向操作：把应用内的文件拖到桌面/资源管理器。必须在渲染进程的拖拽事件中调用：

```ts
// 主进程（已封装在 windowManager.ts 的 drag:start 通道，含防御性校验）
win.webContents.startDrag({
  file: filePath,
  icon: nativeImage.createFromPath('icon.png') // 拖动时显示的图标（Windows 上可选）
})

// 渲染进程
function onDragStart(event: DragEvent): void {
  event.preventDefault() // 关键！取消 HTML5 拖拽循环，把拖拽完全交给原生 startDrag
  window.api.drag.start(filePath) // 通知主进程开始系统拖拽
}
```

**⚠️ 踩坑：Windows 上 drop 时应用闪退**（本工程实测修复）：

- **必须 `event.preventDefault()`**：不取消 HTML5 拖拽的话，DOM 拖拽会话与原生
  `startDrag` 会话并发，drop 时 Chromium 同时收尾两个会话 → 竞态 → 应用闪退
  （Electron 已知崩溃族：electron/electron#26564 等同症状 issue）。官方
  drag-and-drop 教程的示例代码也带 preventDefault。
- **`setData` 对原生拖拽无效**：原生拖拽不读 `dataTransfer`，无需设置（设置了也只是
  服务 HTML5 拖拽，而它已被 preventDefault 取消）。
- **主进程防御**（windowManager.ts 已做）：文件存在性校验（`existsSync`）、
  icon 为空时降级（`createFromPath` 失败/非图片会触发 SetDragImage 崩溃路径）、
  try/catch 兜底（异常记录而非崩溃）。
- **Windows 一次只能拖一个文件**；macOS 要求 icon 非空。

**拖拽图标要点**（本工程实测踩坑）：`startDrag` 的 `icon` **不做缩放**，按原始尺寸
显示在光标下——传 512×512 的应用图标会得到巨大的拖拽光标。正确做法：

```ts
// 优先：文件自身的系统图标（32x32，与 app.getFileIcon 特性同 API）
let icon = await app.getFileIcon(filePath, { size: 'normal' }) // 'small'16 / 'normal'32 / 'large'48
// 兜底：应用图标必须 resize 到小尺寸
if (icon.isEmpty()) {
  icon = nativeImage.createFromPath('icon.png').resize({ width: 32, height: 32 })
}
win.webContents.startDrag({ file: filePath, icon })
```

const icon = await app.getFileIcon(filePath, { size: 'large' }) // 'small'|'normal'|'large'

## 七、进阶：shell 文件操作（`src/main/features/shellOps.ts`）

用系统能力操作文件（比手写 Node 实现更"原生"）：

```ts
import { shell } from 'electron'

await shell.openPath('C:/file.txt')   // 系统默认程序打开（文件/文件夹/URL）
shell.showItemInFolder('C:/file.txt') // 资源管理器中定位
await shell.trashItem('C:/file.txt')  // 移到回收站（可恢复）
shell.beep()                          // 系统蜂鸣
```

渲染进程：

```ts
await window.api.shell.openPath(path)
window.api.shell.showInFolder(path)
await window.api.shell.trash(path)
window.api.shell.beep()
```

> 打开外部链接请用 `shell.openExternal`（不要 openPath，见 docs/12 安全）。

## 八、进阶：目录监听（fs.watch）

文件夹内容变化实时推送（热同步、构建监视器场景）：

```ts
import { watch } from 'fs'

const watcher = watch(dirPath, { recursive: true }, (eventType, filename) => {
  win.webContents.send('fs:watcher-event', { eventType, filename })
})
watcher.close() // 停止监听
```

渲染进程：`window.api.fs.watch(dir)` 开始（返回 id）→ `onWatcherEvent(cb)` 接收变化 → `unwatch(id)` 停止。
Windows/macOS 支持递归监听子目录（Linux 需自行递归实现）。

## 五、安全建议

```ts
// 白名单示例：只允许读写 userData 下的 data 目录
const allowedRoot = app.getPath('userData') + '/data'
if (!filePath.startsWith(allowedRoot)) {
  return { ok: false, error: '路径不在白名单内' }
}
```
