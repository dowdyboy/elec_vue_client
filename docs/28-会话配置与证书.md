# 28 - 会话配置与证书（代理 / UA / 证书校验）

> 对应源码：`sessionConfig.ts` / `certificate.ts` | 演示页：会话管理 ⑤ / 安全实践 ④

## 一、会话代理（session.setProxy）

```ts
// 固定代理（Fiddler/Charles 抓包默认 127.0.0.1:8888）
await session.defaultSession.setProxy({
  mode: 'fixed_servers',
  proxyRules: 'http=127.0.0.1:8888;https=127.0.0.1:8888'
})
// 直连 / 系统代理
await session.defaultSession.setProxy({ mode: 'direct' })
await session.defaultSession.setProxy({ mode: 'system' })
// 查询某 URL 实际走的代理（调试利器）
const proxy = await session.defaultSession.resolveProxy('https://example.com')
```

场景：公司内网代理、抓包调试、流量统计。

## 二、User-Agent 设置

```ts
session.defaultSession.setUserAgent('Mozilla/5.0 ...') // 修改后所有请求携带新 UA
session.defaultSession.getUserAgent()                  // 查询
```

场景：模拟浏览器访问兼容性差的旧网站、标注客户端身份。

## 三、证书校验策略（setCertificateVerifyProc）

```ts
// 放行所有证书（⚠️ 仅测试/内网自签证书场景，生产禁用！）
session.defaultSession.setCertificateVerifyProc((_request, callback) => {
  callback(0) // 0 = 通过
})
// 恢复默认校验
session.defaultSession.setCertificateVerifyProc(null)
```

> ⚠️ trustAll 使任何证书都通过校验 → 中间人攻击者可伪造证书窃取数据。
> 生产环境必须保持系统默认校验；企业内网自签证书更稳妥的做法是
> 把根证书加入系统信任链，而非全局放行。

## 四、复制到新工程的步骤

1. 复制 `sessionConfig.ts` + `certificate.ts`，`index.ts` 调用 `registerSessionConfig()` + `registerCertificate()`
2. 渲染进程：

```ts
await window.api.sessionConfig.setProxy('http=127.0.0.1:8888')
await window.api.sessionConfig.setProxyMode('direct')
await window.api.sessionConfig.setUserAgent('Mozilla/5.0 ...')
await window.api.cert.setVerifyMode('trustAll') // 或 'default'
```
