# 16 - 自定义协议与深链接

> 对应源码：`src/main/features/protocol.ts` | 演示页：协议与深链接

## 一、原理

**深链接**：注册自定义协议（如 `elec-demo://`）后，系统会把该协议的链接交给应用处理。类比：`weixin://`、`magnet://`、`vscode://`。

场景：网页按钮"打开客户端"、邮件里的应用链接、浏览器唤起应用并传参。

**WebContentsView**：在窗口内嵌第三方网页的标准组件（替代已废弃的 BrowserView），适合"应用内嵌帮助文档、H5 页面"。

## 二、关键代码

```ts
const PROTOCOL = 'elec-demo'

// ① 注册为系统默认协议处理程序
if (process.defaultApp) {
  // dev：指向 electron.exe + 入口脚本
  app.setAsDefaultProtocolClient(PROTOCOL, process.execPath, [
    join(process.cwd(), 'out/main/index.js')
  ])
} else {
  app.setAsDefaultProtocolClient(PROTOCOL) // 生产：指向打包 exe
}

// ② 收到链接：Windows/Linux 走 second-instance 的 argv
app.on('second-instance', (_e, argv) => {
  const url = argv.find((a) => a.startsWith(`${PROTOCOL}://`))
  if (url) handleDeepLink(url)
})
// macOS 走 open-url 事件
app.on('open-url', (event, url) => {
  event.preventDefault()
  handleDeepLink(url)
})

// ③ 内嵌网页（WebContentsView）
const view = new WebContentsView({ webPreferences: { sandbox: false } })
win.contentView.addChildView(view)
view.setBounds({ x: 0, y: 0, width, height }) // 铺满窗口
view.webContents.loadURL('https://example.com')
```

## 三、复制到新工程的步骤

1. 复制 `src/main/features/protocol.ts`
2. `index.ts` 中调用 `registerProtocol(getMainWindow)`
3. 渲染进程：

```ts
// 用系统打开协议链接（唤起应用）
window.api.protocol.openUrl('elec-demo://open?from=web')
// 监听收到的深链接
window.api.protocol.onDeepLink((url) => console.log(url))
// 内嵌网页
await window.api.protocol.openView('https://example.com')
await window.api.protocol.closeView()
```

## 四、常见问题

- **dev 模式协议不生效**：需在 `process.defaultApp` 分支传入口脚本参数（代码已处理）
- **单实例配合**：深链接依赖 second-instance 事件，因此应用必须使用单实例锁（见 13-生命周期）
- **macOS 额外要求**：`Info.plist` 需声明 `CFBundleURLTypes`（打包配置中处理）

## 五、扩展：文件关联（open-file）

与深链接类似但针对**文件类型**：打包时声明文件关联，用户双击 .md/.txt 等文件唤起应用：

```yaml
# electron-builder.yml
fileAssociations:
  - ext: md
    name: Markdown 文档
    role: Editor  # macOS
```

处理（`protocol.ts` 已实现）：

```ts
// macOS：双击关联文件触发
app.on('open-file', (event, filePath) => {
  event.preventDefault()
  handleFileOpen(filePath)
})
// Windows/Linux：从启动参数 argv 中识别文件路径
app.on('second-instance', (_e, argv) => {
  const file = argv.find((arg) => !arg.startsWith('-') && /[\\/.]/.test(arg))
  if (file) handleFileOpen(file)
})
```

渲染进程：`window.api.protocol.simulateOpenFile(path)`（模拟触发）+ `onFileOpen(cb)` 接收。

## 六、扩展：内嵌网页导航历史

WebContentsView 内嵌页面的返回/前进（浏览器标准快捷键）：

```ts
// 主进程：view.webContents 上拦截 Alt+←/→
view.webContents.on('before-input-event', (event, input) => {
  if (input.key === 'ArrowLeft' && input.alt) {
    event.preventDefault()
    view.webContents.goBack()
  }
  if (input.key === 'ArrowRight' && input.alt) {
    event.preventDefault()
    view.webContents.goForward()
  }
})
// did-navigate 事件推送导航状态
view.webContents.on('did-navigate', () => {
  win.webContents.send('view:navigation', {
    url: view.webContents.getURL(),
    canGoBack: view.webContents.canGoBack(),
    canGoForward: view.webContents.canGoForward()
  })
})
```

渲染进程：`window.api.protocol.onNavigation(cb)` 接收状态；`goBack()/goForward()` 程序控制。

## 七、扩展：加载状态与脚本注入

**页面加载状态**（`src/main/features/loadState.ts`）：`did-start-loading` / `did-finish-load` / `did-fail-load`
（加载指示器、失败错误页，断网时 `did-fail-load` 触发）。

```ts
contents.on('did-start-loading', () => { /* 显示 loading */ })
contents.on('did-finish-load', () => { /* 隐藏 loading */ })
contents.on('did-fail-load', (_e, code, desc) => { /* 显示错误页 */ })
```

渲染进程：`window.api.web.onLoadState(cb)` 监听（主窗口与内嵌 view 都推送）。

**脚本注入**（`src/main/features/scriptInjection.ts`）：主进程向页面执行 JS 并取回结果
（调试/自动化/埋点）：

```ts
const result = await win.webContents.executeJavaScript('document.title')
```

渲染进程：`window.api.inject.execute('document.title')`（对内嵌 WebContentsView 同样适用）。
⚠️ 能力很强，仅限可信场景。
