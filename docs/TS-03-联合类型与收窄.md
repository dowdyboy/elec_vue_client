# TS-03 - 联合类型与收窄

> 对应演示页：TypeScript 惯用法 → 联合类型与收窄（路由 `/ts/narrowing`）

## 一、惯用法是什么

联合类型（`|`）表达"一个值可能是几种类型之一"；**收窄**是"把联合逐步缩小到
具体分支"。判别联合 + 穷尽检查是 TS 项目最值钱的两个惯用法——状态机、IPC 消息、
UI 状态都用它建模。

## 二、关键代码

```ts
// 基础收窄：typeof / in / instanceof
function handle(input: string | number): number {
  if (typeof input === 'string') return input.length  // 这里 input: string
  return input * 2                                     // 这里 input: number
}

// 判别联合：用一个字面量字段区分分支
interface IdleState { status: 'idle' }
interface LoadingState { status: 'loading'; since: number }
interface ErrorState { status: 'error'; message: string }
type UiState = IdleState | LoadingState | ErrorState

function render(state: UiState): string {
  switch (state.status) {
    case 'idle':     return '等待'
    case 'loading':  return '加载中...' + state.since
    case 'error':    return '错误: ' + state.message
  }
}

// 穷尽检查：加新分支忘处理 → 编译报错
function assertNever(x: never): never {
  throw new Error('未处理的联合分支: ' + JSON.stringify(x))
}
function renderSafe(state: UiState): string {
  switch (state.status) {
    case 'idle':     return '等待'
    case 'loading':  return '加载中'
    case 'error':    return '错误'
    default: return assertNever(state)   // 新增分支忘处理 → 这里报错
  }
}
```

## 三、常见陷阱

- 穷尽检查的 `default` 若直接 `return` 而不调用 `assertNever`，新增分支不会报错，检查失效。
- 分支字段用联合字面量（`'idle' | ...`）而不是 `string`，switch 才能穷尽。

## 四、与 Electron 实例对照

本工程多处事件载荷就是判别联合：
- `src/main/features/autoUpdater.ts` 推送 `{ type: 'checking' } / { type: 'available', version } / { type: 'error', message }`；
- `src/main/features/download.ts` 的 `download:progress` / `download:done` 载荷。
渲染进程（AutoUpdatePage、DownloadPage）按 `status.type` switch 分发，与本节示例同款。
