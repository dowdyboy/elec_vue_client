# TS-10 - 模块与导入导出

> 对应演示页：TypeScript 惯用法 → 模块与导入导出（路由 `/ts/module`）

## 一、惯用法是什么

模块组织决定项目的可维护性：**import type** 与运行时导入要分清、
**re-export / barrel 文件**管理依赖、**路径别名**让代码干净。

## 二、关键代码

```ts
// import type / export type：仅类型导入，运行时被擦除
import type { User } from './types'
import { fetchUser } from './api'
export type { User, Task }

// re-export：中转导出（barrel 文件）
export { fetchUser } from './api'
export type { User } from './types'

// 路径别名：避免深层相对路径（vite/tsconfig 配置 @renderer -> src/renderer/src）
import { useMessage } from 'naive-ui'
// 不用别名时：../../../../components/xxx
// 用别名时：@renderer/components/xxx
```

## 三、常见陷阱

- barrel 文件别过度聚合导致循环依赖；按领域分桶。
- 纯类型模块建议一律 `import type`，明确意图且利于编译优化。

## 四、与 Electron 实例对照

本工程 `src/preload/index.ts` 把 `window.api` 集中定义，并经
`src/preload/index.d.ts` 的 `declare global` 全局暴露给渲染进程——
这是"类型集中声明 + 全局暴露"的范例，让每个调用处都有类型补全。
主进程 `src/main/features/` 每个文件即一个可复制的独立模块（对应 Electron 文档的"复制到新工程"）。
