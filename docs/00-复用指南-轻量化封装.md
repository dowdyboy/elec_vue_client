# 00 - 复用指南（轻量化封装）

> 目标：让本项目的每个特性可被其他 Electron 项目以**简单、独立、安全、轻量**的方式复用，保持教学模板可复制性。

## 一、快速复制（3 步）

以 `clipboard` 为例：

```bash
# 方式 A：脚本一键复制（推荐；会自动补带 types.ts / validateSender.ts 等依赖文件）
npm run copy:feature -- clipboard ../my-app
# 方式 B：手动复制
# 1. 拷贝主进程文件 + 该文件头注释【依赖】段列出的文件
cp src/main/features/clipboard.ts ../my-app/src/main/features/
# 2. 在 ../my-app/src/main/index.ts 中注册
import { registerClipboard } from './features/clipboard'
# app.whenReady 内：registerClipboard()
# 3. 拷贝 preload 分组（搜索 clipboard 定位 api.clipboard）
```

脚本会同步提示：

- 从源码里解析出的**真实** `registerX` 函数名与参数（不是按文件名猜），并打印可直接粘贴的注册代码
- 自动补带的依赖文件（`src/main/types.ts`、`src/main/utils/validateSender.ts`、`src/main/utils/disposable.ts`）
- 需整套一起复制的耦合模块（如 `partition.ts` 依赖 `windowManager.ts` 与 `security.ts`）
- `preload` 中对应 `api.xxx` 分组需手动粘贴的关键词、额外 npm 依赖

## 二、轻量化设计要点

| 目标     | 做法                                                                       | 位置                                                                |
| -------- | -------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| **简单** | 通道名集中登记在 `IPC.*` 目录；失败返回 `{ok:false}` 统一                  | `src/main/ipcChannels.ts` + `ipcChannels.test.ts`                   |
| **易用** | 模板 `_template.ts` + 脚本 `copy-feature.mjs` + 本文档                     | `src/main/features/_template.ts`                                    |
| **独立** | 每个 `registerX(): Disposer` 自闭环，退出时统一 `will-quit` 释放           | `src/main/utils/disposable.ts` `src/main/index.ts:featureDisposers` |
| **安全** | 敏感通道校验 `isTrustedSender(event)`；分区/内嵌网页各自套用会话级权限策略 | `src/main/utils/validateSender.ts` `security.ts`                    |
| **轻量** | 不引入 Pinia/新依赖；`features/` 保持平铺；双 SQLite 保留                  | —                                                                   |

## 三、独立性：资源释放

已为易泄漏模块添加 `Disposer` 返回：

- `fileSystem` → `disposeFileSystemWatchers()` + `ipcMain.removeHandler`
- `socket` → `disposeSockets()`（TCP Server/Client + UDP Sockets）
- `httpServer` → `disposeHttpServer()` + `server.close()`
- `socketServer` → `disposeSocketServer()` + `io.close()`
- `quitGuard` → 移除 `before-quit` 监听与 handlers

`src/main/index.ts` 在 `app.whenReady` 收集到 `featureDisposers`，`app.on('will-quit')` 统一调用（`before-quit` 只置 `setQuitting(true)`，保证 quitGuard 取消时资源未被提前销毁），避免端口占用与 `EADDRINUSE`。

新特性请遵循：

```ts
export function registerYourFeature(getMainWindow): Disposer {
  ipcMain.handle('your:chan', handler)
  return () => {
    ipcMain.removeHandler('your:chan')
    // clearInterval / server.close() 等
  }
}
```

## 四、安全性：最小可用校验

`src/main/utils/validateSender.ts`：

```ts
import { isTrustedSender, FORBIDDEN } from '../utils/validateSender'
ipcMain.handle('shell:openPath', async (e, p) => {
  if (!isTrustedSender(e)) return FORBIDDEN
  // ...
})
```

已内置校验的敏感通道：`shell:openPath/showInFolder/trash` `fileIcon:get` `inject:execute` `cert:setVerifyMode` `fs:*` `protocol:openUrl`。`db:execute`/`db:search(safe=false)` 是**故意保留**的注入对比教学，生产必须加校验或只暴露参数化接口。其他读写类通道建议按需添加。

判定"来源是否可信"统一走 `isTrustedPageUrl()`：打包态只认 `file://`，开发态只认 dev server 同 origin 或回环地址，
按 `new URL()` 解析后**精确比对主机名**——不要写 `origin.includes('localhost')`，`https://localhost.evil.com` 会绕过。

### 分区 / 内嵌网页的会话隔离（权限处理器按 session 生效）

权限处理器是**按 session** 生效而不是按页面，所以两件事必须做，否则白名单形同虚设：

```ts
// 1. 分区窗口（partition.ts 已内置）：独立会话不会继承 defaultSession 的白名单
registerSecurityForSession(session.fromPartition('persist:work'))

// 2. 承载第三方网页的视图（protocol.ts 已内置）：独立内存会话 + 全拒权限
registerDenyAllForSession(session.fromPartition('untrusted-embed'))
// 配合 new WebContentsView({
//   webPreferences: { partition: 'untrusted-embed', sandbox: true, contextIsolation: true }
// })
```

`preload` 的 `MessageChannel` 端口转移已将 `postMessage('*')` 收紧为 `location.origin`（`file://` 下回退 `*`）。

## 五、简单性：通道目录

通道名在主进程、preload、目录三处都会出现，而它们都是字符串：TypeScript **抓不到**拼写错误，
拼错的后果是运行期静默失败（`window.api.xxx()` 的 Promise 永挂起、事件永远不来）。

本工程的处理是"目录 + 测试"两层：

- `src/main/ipcChannels.ts`：`as const` 集中登记**全部**通道（含 `source` / `sweep` / `signalAnalysis` 这些不在 `features/` 下的分组）。
- `src/main/ipcChannels.test.ts`：在 `npm test` 与 CI 里强制三方一致——
  ① preload 用到的通道主进程必须有实现；② 主进程实现/推送的通道必须登记进目录；
  ③ 目录里登记的通道必须真的有实现（防死常量）；④ 目录内不重复。

因此调用处有两种写法，都安全：

```ts
// A. 导入常量：拼错在编译期就报错（推荐）
ipcMain.handle(IPC.window.create, handler)
// B. 继续写字符串：由 ipcChannels.test.ts 在测试期兜底（本工程当前是这种）
ipcMain.handle('window:create', handler)
```

> 历史提示：本工程曾有一份 `src/shared/types.ts` 想"收敛主/preload 重复类型"，
> 但它从未被引用、且副本已经漂移（如 `NotificationOptions` 少了 `actions` 字段），
> 已删除。类型的正确定位是**跟着实现走**：`NotificationOptions` 定义在
> `src/main/features/notification.ts`，preload 直接从那里 `import type`。
