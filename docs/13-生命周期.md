# 13 - 生命周期与单实例

> 对应源码：`src/main/features/appLifecycle.ts` | 演示页：生命周期

## 一、原理

`app` 模块管理整个应用的"生老病死"：

| 能力 | 说明 |
|------|------|
| 单实例锁 | 防止重复启动（双击两次 exe 只弹出一个窗口）|
| 开机自启 | `setLoginItemSettings` 写入系统登录项 |
| 生命周期事件 | `before-quit` → `will-quit` → `window-all-closed` |
| 路径查询 | `app.getPath('userData')` 等常用目录 |

**单实例原理**：第一次启动的实例调用 `requestSingleInstanceLock()` 获得锁；后续启动的实例拿不到锁 → 直接 `app.quit()`，同时第一个实例收到 `second-instance` 事件（聚焦窗口）。

## 二、关键代码

```ts
// ① 单实例锁（必须在 whenReady 前调用）
const gotLock = app.requestSingleInstanceLock()
if (!gotLock) {
  app.quit() // 已有实例在运行，本实例退出
} else {
  app.on('second-instance', () => {
    // 用户再次启动 → 聚焦已有窗口
    win.show()
    win.focus()
  })
}

// ② 开机自启
app.setLoginItemSettings({ openAtLogin: true })
app.getLoginItemSettings().openAtLogin // 查询状态

// ③ 生命周期事件
app.on('before-quit', () => console.log('用户选择退出'))
app.on('will-quit', () => console.log('即将退出，做清理工作'))
app.on('window-all-closed', () => {
  if (process.platform !== 'darwin') app.quit()
})
```

## 三、复制到新工程的步骤

1. 复制 `src/main/features/appLifecycle.ts`
2. `index.ts` 中调用 `registerAppLifecycle(getMainWindow)`（**必须在其他特性之前注册**，因为单实例锁可能直接退出）
3. 渲染进程：

```ts
// 应用信息
const info = await window.api.app.getInfo()

// 开机自启开关
await window.api.app.setLoginItem(true)

// 生命周期事件日志
window.api.app.onLifecycle(({ event }) => console.log(event))
```

## 四、生命周期事件顺序

```
用户点击退出
  → before-quit        （可在此拦截/保存）
  → 所有窗口关闭
  → will-quit          （最后清理：注销快捷键、关连接）
  → quit               （进程结束）
```

> 生产工程建议：`before-quit` 时设 `app.isQuiting = true` 标志，与"关闭窗口隐藏到托盘"逻辑配合。

## 五、扩展：电源监控（`src/main/features/powerMonitor.ts`）

监听系统会话/电源状态，典型场景：唤醒后重连服务器、锁屏时静音：

```ts
import { powerMonitor } from 'electron'

powerMonitor.on('lock-screen', () => { /* 用户锁屏 */ })
powerMonitor.on('unlock-screen', () => { /* 解锁 */ })
powerMonitor.on('suspend', () => { /* 系统睡眠 */ })
powerMonitor.on('resume', () => { /* 系统唤醒 */ })
powerMonitor.on('shutdown', () => { /* 关机前保存数据 */ })
powerMonitor.on('on-battery', () => { /* 切电池（部分平台） */ })

powerMonitor.onBatteryPower      // 是否电池供电
powerMonitor.getSystemIdleTime() // 系统空闲秒数
```

## 六、扩展：全局错误处理（`src/main/features/errorHandler.ts`）

生产应用兜底：捕获异常不崩溃、记录并上报：

```ts
// 主进程未捕获异常（防崩溃退出）
process.on('uncaughtException', (error) => {
  console.error(error)
  // 生产：上报到 sentry 等平台
})
// 未处理 Promise 拒绝
process.on('unhandledRejection', (reason) => { /* 记录 */ })
// 渲染进程崩溃（可提示用户"页面崩溃"）
app.on('render-process-gone', (_e, _wc, details) => {
  // details.reason: clean-exit / crashed / killed ...
})
// 子进程异常（GPU/网络）
app.on('child-process-gone', (_e, details) => { /* 记录 */ })
```

## 七、扩展：阻止系统睡眠（`src/main/features/powerBlocker.ts`）

下载/播放/演示时保持系统唤醒：

```ts
import { powerSaveBlocker } from 'electron'

const id = powerSaveBlocker.start('prevent-app-suspension')
// 另有 'prevent-display-sleep'：连屏幕都不让休眠
powerSaveBlocker.stop(id)
powerSaveBlocker.isStarted(id) // 查询状态
```

渲染进程：`await window.api.powerBlocker.set(true/false)`

## 八、扩展：应用重启（`src/main/features/relaunch.ts`）

主动重启场景：设置项"重启生效"、自动更新安装前：

```ts
import { app } from 'electron'

app.relaunch() // 安排重启（注册为启动参数）
app.exit(0)    // 立即退出进程（不走 before-quit 流程）
```

渲染进程：`await window.api.relaunch.now()`

> 若需走正常退出流程（保存数据/清理），用 `app.quit()` 代替 `app.exit(0)`。

## 九、扩展：退出前未保存询问（`src/main/features/quitGuard.ts`）

生产必备："有未保存修改，确定退出？"：

```ts
// 页面标记"有未保存修改"（如编辑器内容变化时）
await window.api.quitGuard.setDirty(true)

// 主进程 before-quit 拦截 + 询问
app.on('before-quit', (event) => {
  if (!hasUnsaved || forceQuit) return
  event.preventDefault() // 拦截退出
  const result = dialog.showMessageBoxSync({
    type: 'warning', message: '存在未保存的修改，确定要退出吗？',
    buttons: ['直接退出', '取消'], cancelId: 1
  })
  if (result === 0) { hasUnsaved = false; forceQuit = true; app.quit() }
  else { quitState.isQuitting = false } // 取消：复位退出状态（保持"关闭=隐藏托盘"行为）
})
```

实现要点：`quitState` 与 index.ts 共享（取消时复位 isQuitting，否则窗口关闭拦截失效）；`forceQuit` 防止二次询问死循环。

## 十、扩展：崩溃转储（crashReporter）

官方崩溃报告 API：进程崩溃时生成 .dmp 文件（生产配合 uploadToServer 上报）：

```ts
import { crashReporter } from 'electron'

crashReporter.start({
  productName: 'my-app',
  uploadToServer: false, // 本地转储（不上报）
  submitURL: ''
})
// 转储目录
app.getPath('crashDumps')
```

与 errorHandler 的 `render-process-gone` 捕获互补：事件捕获做"UI 提示/自动恢复"，
crashReporter 做"崩溃证据收集"。完整生产方案接入 sentry（docs/21）。
