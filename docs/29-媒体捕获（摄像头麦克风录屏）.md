# 29 - 媒体捕获（摄像头/麦克风预览与录制 + 桌面录屏）

> 对应源码：`src/main/features/security.ts`（权限白名单） | 演示页：媒体捕获

## 一、技术链路全景

```
页面调用 getUserMedia / getDisplayMedia
        │
        ▼
session.setPermissionRequestHandler（security.ts 白名单裁决 media / display-capture）
        │ 放行
        ▼
macOS 额外一道锁：系统隐私设置（systemPreferences.askForMediaAccess）
        │
        ▼
拿到 MediaStream → <video> 预览 → MediaRecorder 录制 webm
```

**关键认知**：摄像头/麦克风/录屏的"采集"与"录制"全部发生在渲染进程（浏览器 API），
主进程只负责**权限裁决**。这与 desktopCapturer（主进程枚举源 + 截图）的分工不同：
`getDisplayMedia` 是持续媒体流（录屏），`desktopCapturer.capturePage` 是静态截图。

## 二、权限白名单（主进程）

```ts
// security.ts：只放行白名单内的权限，其余拒绝并通知页面
const allowedPermissions = new Set(['clipboard-read', 'media', 'display-capture'])

session.defaultSession.setPermissionRequestHandler((webContents, permission, callback) => {
  callback(allowedPermissions.has(permission))
})
```

权限字符串：摄像头/麦克风为 `'media'`；录屏（getDisplayMedia）为 `'display-capture'`。
**两者都必须进白名单**，否则请求会被主进程直接拒绝（getUserMedia 抛 NotAllowedError /
getDisplayMedia 抛 InvalidStateError）。漏加 display-capture 是录屏功能最常见的"莫名其妙失败"原因。

## 三、摄像头/麦克风（渲染进程）

```ts
// 1. 申请媒体流（会触发上面的权限处理器）
const stream = await navigator.mediaDevices.getUserMedia({ video: true, audio: true })
// 2. 预览：video 元素绑定流
videoEl.value.srcObject = stream
// 3. 录制：MediaRecorder 输出 webm 流
const recorder = new MediaRecorder(stream, { mimeType: pickWebmMime() })
recorder.ondataavailable = (e) => chunks.push(e.data)
recorder.onstop = () => {
  const blob = new Blob(chunks, { type: 'video/webm' })
  playbackEl.src = URL.createObjectURL(blob) // 回放
}
recorder.start()
// 4. 释放：所有轨道 stop（指示灯熄灭，资源回收）
stream.getTracks().forEach((t) => t.stop())
```

## 四、桌面录屏（渲染进程 + 主进程 handler）

**⚠️ 最大坑点：Electron 默认不支持 getDisplayMedia！** 浏览器里"自带屏幕选择器"的行为
在 Electron 中不存在——不注册主进程 handler 直接调用会抛 `NotSupportedError`
（这是最常见的"录屏莫名失败"原因）。必须注册 `session.setDisplayMediaRequestHandler`：

```ts
// 主进程（本工程 desktopCapture.ts）：handler 接管授权，配合应用内弹窗
session.defaultSession.setDisplayMediaRequestHandler((request, callback) => {
  if (!request.videoRequested) return callback({}) // 本演示只支持视频
  const requester = request.frame ? webContents.fromFrame(request.frame) : null
  if (!requester) return callback({}) // 帧已销毁
  desktopCapturer.getSources({ types: ['screen', 'window'], thumbnailSize: { width: 320, height: 180 } })
    .then((sources) => {
      // 枚举结果推给发起窗口弹窗选择（token 模式关联回调，30s 超时 + destroyed 兜底）
      requester.send('capture:display-sources', { token, sources })
      pendingDisplays.set(token, (streams) => callback(streams))
    })
})
// 渲染层回传选择后：callback({ video: { id: sourceId, name: sourceName } })
// 取消/超时/窗口销毁：callback({}) → Chromium 拒绝 Promise（页面 catch 兜底）
```

```ts
// 渲染进程：调用方式与浏览器一致（授权走上面的 handler + 应用内弹窗）
const stream = await navigator.mediaDevices.getDisplayMedia({ video: true, audio: false })
// 用户点击浏览器自带的"停止共享"条时同步状态
stream.getVideoTracks()[0].addEventListener('ended', stopScreen)
// 录制与上面 MediaRecorder 完全相同
```

设计选择：官方还提供 `useSystemPicker: true`（用系统原生选择器），但**仅 macOS 且标记
experimental**，跨平台体验不可控；本工程用"应用内选择器"（desktopCapturer 缩略图弹窗，
与串口页的"接管 Chromium 选择器"同一模式）。

> 权限顺序：`display-capture` 白名单（security.ts 请求处理器）→ displayMediaRequestHandler
> 授权。两者缺一：缺白名单抛 NotAllowedError，缺 handler 抛 NotSupportedError。

**保存录屏联动下载管理**：`<a href={blobUrl} download="xxx.webm">` 触发下载时，
Electron 会走 `will-download` 事件 → download.ts 的完整进度链路。

**CSP 注意（易踩坑）**：回放用 `blob:` 地址，若应用配置了 CSP（本工程 index.html），
`media-src` 必须放行 blob，否则 `<video>` 加载失败：

```html
<meta http-equiv="Content-Security-Policy"
      content="default-src 'self'; media-src 'self' blob:; ..." />
```

## 五、macOS 双重权限（容易踩坑）

macOS 上即使应用白名单放行了 `media`，**系统隐私设置**未授权时 `getUserMedia` 仍会失败：

```ts
// systemAccess.ts：引导用户到系统设置授权
const granted = await systemPreferences.askForMediaAccess('camera')
const status = systemPreferences.getMediaAccessStatus('microphone') // 'granted' | 'denied' | ...
```

授权状态会记忆：第一次询问后，用户可在 系统设置 → 隐私与安全性 → 摄像头/麦克风 修改。

## 六、复制到新工程的步骤

1. 主进程：复制 `security.ts`（或在新工程 session 上设置同样的权限白名单，
   记得放行 `'media'` 与 `'display-capture'`）
2. macOS 需要：复制 `systemAccess.ts` 的授权询问（可选）
3. 渲染进程：复制演示页的 getUserMedia / getDisplayMedia / MediaRecorder 三段代码
4. 无需新增 IPC 通道（全部是浏览器 API；仅权限裁决在主进程）

> 扩展方向：MediaRecorder 换 ffmpeg 落盘 mp4、虚拟背景（Canvas + getUserMedia）、
> 屏幕共享到 WebRTC（getDisplayMedia 作为 peer 输入源）、音频可视化（Web Audio API）。
