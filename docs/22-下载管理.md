# 22 - 下载管理

> 对应源码：`src/main/features/download.ts` | 演示页：下载管理

## 一、原理

下载功能的两层能力：

| 能力 | 事件/API | 说明 |
|------|---------|------|
| 触发下载 | `webContents.downloadURL(url)` | 走 Chromium 网络栈 |
| 管理下载 | `session` 的 `will-download` 事件 + `DownloadItem` | 保存路径、进度、暂停/恢复/取消 |

**will-download** 在每次下载开始时触发：可修改保存路径、拦截（`event.preventDefault()` 后自行处理）、记录日志。

## 二、关键代码

```ts
session.defaultSession.on('will-download', (_event, item) => {
  // 默认保存到系统下载目录；可在"数据目录"页运行期 setPath('downloads', ...) 修改
  item.setSavePath(join(app.getPath('downloads'), item.getFilename()))

  // 进度更新（progressing | interrupted）
  item.on('updated', (_e, state) => {
    const percent = item.getReceivedBytes() / item.getTotalBytes()
  })

  // 完成（completed | cancelled | interrupted）
  item.on('done', (_e, state) => { /* 通知渲染进程 */ })
})

// 触发下载
win.webContents.downloadURL('https://example.com/file.zip')
// 控制
item.pause() / item.resume() / item.cancel()
```

## 三、复制到新工程的步骤

1. 复制 `src/main/features/download.ts`
2. `index.ts` 中调用 `registerDownload(getMainWindow)`
3. 渲染进程：

```ts
await window.api.download.start('https://example.com/file.zip')
window.api.download.onProgress(({ percent, filename }) => { /* 更新进度条 */ })
window.api.download.onDone(({ state, savePath }) => { /* 完成/失败处理 */ })
await window.api.download.pause(url) // 暂停（按 URL 管理）
```

## 四、最佳实践

- **保存路径**：生产环境用 `item.setSaveDialogOptions()` 弹保存框，或自定义下载目录 + 文件名冲突处理
- **中断续传**：`interrupted` 后可调用 `item.resume()` 续传（需服务器支持 Range）
- **下载与 webRequest**：下载请求也走 Chromium 栈，可被拦截（见 docs/23）
- **⚠️ canResume() 语义陷阱**（本工程实测踩坑）：它表示"能否**恢复**"——仅对
  `paused`/`interrupted` 状态返回 true，对**正在下载**的项返回 false。判断"能否暂停"
  要用 `item.isPaused()`/状态，别拿 canResume 当暂停守卫（否则正常下载会被挡下，
  提示"没有可暂停的下载"）
- **⚠️ 状态事件映射缺口**（Electron 39 源码级确认）：`updated`/`done` 事件的 state
  转换器（gin Converter）只有 progressing/completed/cancelled/interrupted 四个分支，
  **PAUSED 落入 default 返回空串**——暂停时页面收到的 state 是 `''`。因此暂停/恢复
  状态必须由应用主动推送（本工程 download.ts 的 `download:state` 通道）：

```ts
ipcMain.handle('download:pause', (_e, id) => {
  item.pause()
  push('download:state', { id, state: 'paused' }) // 应用层状态机推送
})
```

- **⚠️ "真暂停"需要服务端配合**（本工程实测踩坑）：`item.pause()` 会让 Chromium
  停止**读取 socket 与写磁盘**，但如果服务器无视背压继续灌数据，网络层仍会持续
  传输（表现为"后台还在下载"、恢复后瞬间完成）。完整闭环：

  | 环节 | 客户端 | 服务器 |
  |------|--------|--------|
  | 断点数据 | `resume()` 发起 Range 请求 | 支持 206/Content-Range |
  | 真停止传输 | pause 后停止读取 socket | **尊重背压**：`res.write` 返回 false 时挂 `drain` 再继续（本工程 /download 端点已实现） |

  无 Range 时 `canResume()` 为 false 无法恢复；无背压则暂停只是"磁盘不写、网络照传"。

## 五、自闭环下载源（本工程实测踩坑）

演示页原默认地址 `https://speed.hetzner.de/10MB.bin`（德国测速文件）在国内网络基本
不可达，点击下载后立即 `interrupted`——不是代码问题而是**演示源可用性**问题。
为此 httpServer.ts 新增了 `/download` 端点，实现完全自闭环：

```
GET http://127.0.0.1:8765/download?size=20&delay=10
```

| 参数 | 含义 | 默认 |
|------|------|------|
| `size` | 文件大小 MB（上限 100） | 20 |
| `delay` | 每 64KB 块的间隔 ms（模拟网速，便于观察进度/暂停） | 10 |

实现要点：

- 数据为 64KB 重复模式块（不真实分配大内存）；`Content-Length` + `Content-Disposition`
  保证 `item.getFilename()` 得到 `demo-20MB.bin`
- **支持单段 Range（206 + Content-Range）**——`DownloadItem.pause()/resume()` 的
  `canResume()` 前提，本地即可完整实测"暂停 → 恢复 → 完成"链路

**interrupted 排查**：状态 interrupted 表示连接中断（网络不可达/超时）——
国内优先用本地预设；外网演示源失败属预期（真实失败链路同样是教学的一部分）。
下载走主进程 `webContents.downloadURL`（Chromium 栈），不受渲染进程 CSP 影响，
但会受 session 代理/UA 配置影响（见 docs/28）。
