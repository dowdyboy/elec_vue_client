# 12 - 安全实践

> 对应源码：`src/main/features/security.ts` | 演示页：安全实践

## 一、原理

Electron 应用 = Chromium + Node.js，两者结合带来了强大的能力，也带来巨大攻击面。安全基线：

1. **contextIsolation: true**（默认）：渲染进程与 Node 隔离，preload 只暴露白名单 API（本工程 preload/index.ts 是范例）
2. **sandbox: true**（生产推荐）：渲染进程运行在沙箱中，进一步限制能力
3. **权限白名单**：页面请求摄像头/麦克风/剪贴板等权限，必须经主进程裁决
4. **导航拦截**：防止页面被引导跳转到外部网站（防钓鱼）
5. **禁用 webview**：webview 是高风险组件，默认应禁用
6. **CSP**：为渲染进程配置内容安全策略

## 二、关键代码

```ts
import { session } from 'electron'
import { isTrustedPageUrl } from '../utils/validateSender'

// ① 权限白名单：只放行明确授权的权限，且只有「本应用自己的页面」有资格申请
const allowed = new Set(['clipboard-read'])
session.defaultSession.setPermissionRequestHandler((wc, permission, callback, details) => {
  const trusted = isTrustedPageUrl(details.requestingUrl ?? wc.getURL())
  if (trusted && allowed.has(permission)) {
    callback(true)
  } else {
    callback(false)
    if (trusted) wc.send('security:permission-denied', permission) // 通知页面
  }
})

// ② 导航拦截：所有 webContents 创建时挂载
app.on('web-contents-created', (_e, contents) => {
  contents.on('will-navigate', (event, url) => {
    if (!isInternalUrl(url)) {
      event.preventDefault()
      shell.openExternal(url) // 转交系统浏览器
    }
  })
  // ③ 禁用 webview
  contents.on('will-attach-webview', (event) => event.preventDefault())
})
```

> **为什么必须加 `isTrustedPageUrl`**：权限处理器是**按 session** 生效的，不是按页面。
> 同一个 session 里只要有第三方页面（本工程的"内嵌网页"演示就是），它同样命中这个处理器——
> 只判权限名，等于把摄像头/麦克风/串口交给任意网页。判定要按 URL 解析后精确比对主机名，
> 不要用 `includes('localhost')`（`https://localhost.evil.com` 会绕过）。

⚠️ **两套机制别混淆**（本工程演示页曾因此被误读）：

- **权限白名单**（`setPermissionRequestHandler`）：页面请求浏览器权限（摄像头/麦克风/地理位置/通知等）→ 白名单外**拒绝**，并推送 `security:permission-denied` 记录。演示页 ① 用 `navigator.geolocation` 触发（白名单外 → 被拒并记录）。
- **窗口/导航拦截**（`setWindowOpenHandler` / `will-navigate`）：`window.open` 或跳转外部站点 → **转交系统浏览器打开**（`shell.openExternal`），应用内不新开窗口。"打开浏览器"是预期设计，不是拦截失效。演示页 ② ③ 演示。

### 补充：两个权限处理器的区别

| 处理器                        | 交互方式                     | 适用                                                          |
| ----------------------------- | ---------------------------- | ------------------------------------------------------------- |
| `setPermissionRequestHandler` | 有回调（可通知页面"被拒绝"） | 用户可见的权限请求（security.ts ①）                           |
| `setPermissionCheckHandler`   | 无 UI 静默返回 boolean       | permissions.query 等无界面查询（security.ts ①.5，可开关演示） |

两者共用同一白名单，生产按需组合使用。

CSP（渲染进程 index.html 中）：

```html
<meta
  http-equiv="Content-Security-Policy"
  content="default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'"
/>
```

### 补充：IPC 发送方校验与分区 session

- **所有敏感 IPC handler 先校验发送方**：`isTrustedSender(event)`（`src/main/utils/validateSender.ts`），不通过返回 `FORBIDDEN`。本工程的 `certificate/fileIcon/scriptInjection/shellOps/fs/protocol` 等已接入；`db:execute`/`db:search(safe=false)` 是为教学故意保留的注入对比，**生产必须加校验/只暴露参数化接口**。
- **preload 不暴露完整 electronAPI**：`window.electron` 只保留 `platform/versions`，不再挂 `ipcRenderer`/`process.env`；渲染进程只能走 `window.api` 白名单。
- **生产导航拦截**：`security.ts` 对空的 `ELECTRON_RENDERER_URL` 做了判断，避免 `startsWith('')` 恒真绕过 `will-navigate`。
- **权限处理器按 session 生效，不按页面**：`registerSecurity()` 只给 `defaultSession` 挂「白名单 + 来源校验」；其余 session 必须各自处理，否则退回 Electron 默认行为（默认放行）：
  - 分区窗口（[partition.ts](../src/main/features/partition.ts)）：创建窗口前已自动调用 `registerSecurityForSession(session.fromPartition(partition))`；
  - 承载第三方网页的视图（[protocol.ts](../src/main/features/protocol.ts)）：用独立内存分区 `untrusted-embed` + `registerDenyAllForSession(...)` 全拒权限，并设 `sandbox: true`、无 preload。
- **教学/受控场景的收紧点**：`cert:setVerifyMode('trustAll')` 仅调试用；`inject:execute` 限制 5000 字符且需可信发送方；文件图标路径限制 1024 字符；`db:execute` / `db:search(safe=false)` 是**故意保留**的注入对比教学，生产必须加校验或只暴露参数化接口。

## 三、复制到新工程的步骤

1. 复制 `src/main/features/security.ts`（以及它依赖的 `src/main/utils/validateSender.ts`）
2. `index.ts` 中调用 `registerSecurity()`；分区窗口用 `registerSecurityForSession(session.fromPartition(partition))`，承载第三方网页的视图用 `registerDenyAllForSession(...)`
3. 渲染进程监听权限拒绝事件：

```ts
window.api.security.onPermissionDenied((permission) => {
  // 提示用户权限被拒绝
})
```

## 四、安全清单（上线前自查）

- [ ] `contextIsolation: true`（永远开启）
- [ ] `sandbox: true`（生产环境）
- [ ] `nodeIntegration: false`（永远关闭）
- [ ] 外部链接一律 `shell.openExternal`
- [ ] 权限白名单按需最小化
- [ ] 所有敏感 IPC handler 校验 `isTrustedSender(event)`
- [ ] 分区窗口单独调用 `registerSecurityForSession`
- [ ] 渲染进程配置 CSP
- [ ] 不信任渲染进程传来的任意路径（文件操作需白名单）
