# TS-09 - 异步惯用法

> 对应演示页：TypeScript 惯用法 → 异步惯用法（路由 `/ts/async`）

## 一、惯用法是什么

async/await 之外，真正让项目好维护的是**错误处理模式**与**并发组合**：
类型化错误、结果对象（Result）、`Promise.allSettled` 批量任务。
Electron 的 IPC 调用本身就是 Promise，天然适用这些模式。

## 二、关键代码

```ts
// async 函数永远返回 Promise<T>；await 解包
async function fetchUser(id: string): Promise<User> {
  const res = await fetch(`/api/user/${id}`)
  if (!res.ok) throw new Error('请求失败: ' + res.status)
  return (await res.json()) as User
}

// 类型化错误
class ApiError extends Error {
  constructor(public status: number, message: string) {
    super(message)
  }
}

// 结果对象（Go 风格），避免层层 try/catch
type Result<T> = { ok: true; value: T } | { ok: false; error: string }
async function fetchResult(id: string): Promise<Result<User>> {
  try {
    return { ok: true, value: await fetchUser(id) }
  } catch (error) {
    return { ok: false, error: error instanceof Error ? error.message : String(error) }
  }
}

// 并发组合
const [a, b] = await Promise.all([p1(), p2()])        // 全部成功才继续
const winner = await Promise.race([p1(), timeout()])  // 谁先完成用谁
const settled = await Promise.allSettled([p1(), p2()]) // 逐个不中断

// allSettled 批量任务：不因单个失败中断
async function loadAll(ids: string[]): Promise<User[]> {
  const results = await Promise.allSettled(ids.map(fetchUser))
  return results
    .filter((r): r is PromiseFulfilledResult<User> => r.status === 'fulfilled')
    .map((r) => r.value)
}
```

## 三、常见陷阱

- `Promise.all` 任一 reject 会整体失败；失败容忍场景要用 `allSettled`。
- 捕获的 `error` 是 `unknown`，必须用 `instanceof`/守卫收窄后再访问属性。

## 四、与 Electron 实例对照

本工程 IPC 的 `window.api.xxx()` 都是 Promise：handler 返回
`{ ok, error | path }` 等**结果对象**（与 Result 惯用法一致），渲染进程
`if (res.ok) ... else message.error(res.error)`——这正是"判别联合 + Result"
在跨进程边界的落地（见 TS-12）。
